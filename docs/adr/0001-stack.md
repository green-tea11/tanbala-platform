# ADR-0001: Стек WhatsApp-консультанта

**Дата**: 2026-10-25
**Статус**: accepted
**Кто решал**: оркестратор Claude Code и агенты ECC (архитектор, исследователь, безопасник) по плану владельца. Утверждён владельцем 25.10.2026.

## Контекст

План фиксирует Baileys для WhatsApp, Claude Haiku через Anthropic API, свою веб-панель и VPS на PS.KZ: переписки хранятся на сервере в Казахстане. Номер один, трафика мало. Бюджет API общий с системой писем, поэтому тесты только на моках, а каждый вызов пишется в лог. Код будут писать и менять агенты: нужны строгие типы и быстрые автоматические проверки.

## Решение

Один процесс на Node.js 22 LTS и TypeScript 6.0 (ESM, strict). Версии всех зависимостей точные.

| Часть | Выбор |
|---|---|
| WhatsApp | `baileys` 7.0.0-rc14 |
| LLM | `@anthropic-ai/sdk` 0.135.0, Claude Haiku (`claude-haiku-5-5`), модели в `config/models.json` |
| База | SQLite через `better-sqlite3` 13 |
| Веб-панель | `fastify` 5.12 |
| Логи | `pino` 10, лог токенов в JSON Lines |
| Настройки | `.env` с проверкой через `zod` 4 |
| Голос (этап 7) | встроенный `fetch` к OpenRouter, без отдельного SDK |
| Тесты | `vitest` 5: только моки, сеть в тестах заблокирована |
| Разработка | `tsx`, `tsc`, ESLint 10 с typescript-eslint, Prettier, npm |

Внешние библиотеки подключаются только в своих адаптерах (`src/whatsapp`, `src/llm`, `src/db`, `src/panel`), остальной код работает через интерфейсы из `src/domain` и тестируется на моках. Правило проверяет `tests/guards/architecture.test.ts`.

## Рассмотренные альтернативы

### Baileys 6.7.24 (legacy)
- **Плюсы**: больше примеров в интернете.
- **Минусы**: мейнтейнеры объявили 6.x неподдерживаемой; нет полей LID, на которые WhatsApp уже переводит контакты; libsignal ставится прямо из git.
- **Почему нет**: новый проект на заброшенной ветке.

### PostgreSQL
- **Плюсы**: параллельная запись, запас на рост.
- **Минусы**: отдельный сервис на VPS со своими обновлениями и бэкапами.
- **Почему нет**: один номер и один процесс; SQLite хватает, бэкап одним файлом.

### node:sqlite (встроен в Node 22)
- **Почему нет**: в Node 22 он ещё экспериментальный.

### Express 5 или Hono
- **Почему нет**: у Fastify есть официальные плагины cookie, rate limit, helmet и CSRF, которые нужны панели, и `inject()` для тестов без сети.

### TypeScript 7
- **Почему нет**: typescript-eslint пока поддерживает TypeScript только до 6.0. Перейдём, когда поддержка появится.

### Anthropic SDK 1.x
- **Почему нет сейчас**: вся линия 1.x вышла за последние дни (четыре релиза с 21 по 23.10.2026). По правилу карантина берём версии старше 7 дней. Решим на этапе 3, до первых реальных вызовов.

### Python
- **Почему нет**: Baileys есть только для Node.js.

## Последствия

### Плюсы
- Один процесс и один файл базы: просто развернуть, бэкап одним файлом, переписки не покидают сервер.
- Строгие типы, ESLint и тесты на моках ловят ошибки до запуска и без расходов на API.
- Адаптеры заменяемы: например, Baileys на официальный Cloud API, если Baileys заглохнет.

### Минусы
- Нативные модули (better-sqlite3, sharp) нужны под платформу. Готовые бинарники для Windows x64 и Linux x64 есть, сборка не нужна.
- Baileys в статусе RC: обновлять вручную, отдельным коммитом и после проверки.

### Риски
- **Поддержка Baileys застыла**: последнее слияние 05.08.2026. С 28.07 привязка нового номера по QR на rc14 проходит не у всех (issue #2737, исправление в несмёрженном PR #2765). На этапе 2 не больше двух или трёх попыток привязки в день: частые неудачи WhatsApp наказывает блокировкой привязки. Запасной путь: свой обработчик `companion_reg_refresh` или патч по PR #2765.
- **Бан номера** (риск принят в плане): только ответы на входящие, пауза и статус «печатает», лимиты исходящих.
- **Уязвимости**: Baileys ниже 7.0.0-rc12 уязвим (CVE-2026-48063, CRITICAL). Форки вроде `lotusbail` вредоносные, ставим только пакет `baileys`.
- **Лицензия**: `libsignal` (зависимость Baileys) под GPL-3.0. Пока бот работает только на нашем сервере и не распространяется, раскрывать код не нужно.
- **Цепочка поставок**: в `.npmrc` включены `ignore-scripts`, `save-exact` и `engine-strict`, lockfile в git. На 25.10.2026 `npm audit` не находит уязвимостей, подписи реестра проверены у всех пакетов.
- **Персональные данные**: тексты клиентов уходят в Anthropic, а голосовые в OpenRouter, то есть за пределы РК. Трансграничную передачу оценивает владелец.
