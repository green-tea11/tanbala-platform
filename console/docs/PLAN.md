# Единая панель Tanbala: план (этап 0)

30.10.2026. Статус: принят владельцем 30.10.2026; этапы 1 и 2 идут параллельно, стоп после этапа 2. Срок: 1 ноября.

Разбор кода: 6 агентов (опись обеих панелей, независимая проверка каждой описи, источники данных, сервер и
безопасность). Подробности: `FEATURES.md` (181 функция старых панелей), `research/data-sources.md`,
`research/deploy-security.md`, `research/integration.md`.

## 1. Коротко

- Новая папка `console/`, своя служба `tanbala-console` на `127.0.0.1:3200`, адрес `panel.tanbala.kz`.
- Данные и действия консоль берёт только через JSON-эндпоинты почты и бота на `127.0.0.1` со своим токеном.
  Эндпоинты вызывают **те же функции**, что старые кнопки, со всеми проверками.
- Свой вход: имя и пароль (от 9 символов), сессии, CSRF, ограничение попыток, журнал действий. Пароль Caddy остаётся
  сверху.
- Бот и почта не меняют поведения: в них добавляются только эндпоинты и вынос логики кнопок в общие функции, старые
  тесты проходят без правок.
- Старые панели работают параллельно до «ок» на переключение, потом wa. и leads. перенаправляются на panel.

## 2. Архитектура

```
браузер ── https ── Caddy (basic auth) ── 127.0.0.1:3200  console (Node 22, fastify, SQLite: пользователи,
                                                          │  сессии, журнал, «просмотрено»)
                                     X-Console-Token      ├── 127.0.0.1:8000 /internal/console/*  почта (FastAPI)
                                                          └── 127.0.0.1:3101 /internal/console/*  бот (fastify)
```

### console/

- Сервер: Node 22.23.2, TypeScript, fastify 5.12.7, zod, pino, better-sqlite3 13.0.3 — те же версии, что у бота
  (на сервере уже работают, sqlite3 приезжает готовым бинарником).
- Интерфейс: Vite + React + TypeScript, одна страница (SPA). Вид и библиотеки оформления решает этап 3 по Taste.
- Собирается **на ПК**, как сайт: `build-release.sh` кладёт готовый `dist/` в архив. На сервере 2 ГБ, сборка Vite во
  время поиска ушла бы в swap, и на сервере не нужны пакеты разработки.
- Консоль — посредник (BFF): токены к почте и боту лежат только в её `.env`, браузер их не видит. Главную и карточку
  клиента консоль собирает из двух ответов сама.
- Если бот или почта не отвечают, их разделы показывают «недоступно», остальное работает. Бот до привязки по QR
  не запущен: раздел WhatsApp пишет «бот не запущен».

### Эндпоинты почты: `/internal/console/*` на 127.0.0.1:8000

Под префиксом `/internal` они сразу получают готовую защиту: только Host 127.0.0.1, без прокси-заголовков, 404 в
Caddy, строка запроса не пишется в лог. Токен свой: `LEADS_CONSOLE_TOKEN`, заголовок `X-Console-Token` (у бота —
другой, `WA_CONSOLE_TOKEN`; приложения не стартуют, если токены совпадают). Токен бота (`INTERNAL_API_TOKEN`) к ним
не подходит: бот по nftables может ходить на 8000, и его взлом не должен давать права одобрять письма или запускать
поиск. Контракт бота `/internal/*` не меняется. Точные поля — `contract/CONSOLE_API.md`.

**Старый интерфейс почты уходит на свой порт 8001** (решение владельца по риску 3, сделано раньше переключения,
потому что проверка Host или Origin его не закрывает: локальный процесс подставит любые заголовки). На 8000
остаётся только `/internal/*`, к 8001 nftables пускает только Caddy. Старый интерфейс работает как прежде через
leads.tanbala.kz, но взломанный бот его кнопки больше не нажмёт.

- Чтение: сводка (идущий запуск, проверки из WhatsApp, письма на проверке, расход день и месяц по моделям, бюджет,
  лимиты: проверки за день из `RESEARCH_PER_DAY`, тестовые отправки из 30, тестовый адрес); компании с фильтрами
  (старые и новые: «из WhatsApp», «писал в WhatsApp», «не писать», «есть письмо», сортировка); карточка компании;
  компании по списку id (для связки с чатами); письма и письмо; запуски и ход запуска; варианты поиска (города,
  подсказки отраслей, лимиты, цена); история писем и «не писать»; **проверки из WhatsApp (research_jobs)** — экрана
  для них сейчас нет совсем.
- Действия: запуск поиска, одобрить, отклонить, изменить, тестовая отправка, «Больше не писать», «Снять отметку
  WhatsApp», импорт «Уже писали» и «Не писать».
- Логика кнопок сейчас — замыкания внутри `create_app`. Выносим её в `web/actions.py`, старые HTML-маршруты и новые
  JSON вызывают одно и то же: 409 «не писать», триггеры базы на компании из WhatsApp, 30 тестов в сутки, бюджет,
  один запуск сразу. «Кто одобрил» — имя пользователя консоли (сейчас всегда «владелец»).

### Эндпоинты бота: отдельный fastify на 127.0.0.1:3101 в том же процессе

Хуки старой панели (вход, Origin, CSRF, только формы) висят на всём сервере 3100, поэтому JSON туда не встроить без
правки этих хуков. Отдельный маленький сервер на 3101 стартует и останавливается вместе с панелью, Caddy до него не
дотянется ни при какой ошибке в Caddyfile, в nftables к нему пускается только консоль.

- Чтение: состояние (WhatsApp подключён, `TEST_MODE`, размер списка разрешённых, номер менеджера задан, определение
  компании включено, вызовы API за сутки из 500); «требует внимания» (открытые передачи и дошло ли уведомление,
  горячие, ждут ответа, чаты простоя); чаты с фильтрами и поиском; карточка чата (то же, что `loadChatPage`, плюс
  история передач, почему такой уровень); листание переписки; уведомления менеджеру; чаты по id компаний; расход
  по `token-usage.jsonl` (токены по дням и моделям).
- Действия: ответ клиенту, «Вернуть боту». Логика из `routes-chats.ts` выносится в `panel/chat-actions.ts` без
  изменения поведения: тот же порядок (проверка текста → можно ли отправить → защита от дубля 10 с → перехват →
  отправка), то же окно дубля для старой и новой панели.
- **«Вернуть боту» с двумя полями.** Сейчас у бота одно поле «Заметка для бота» (до 1000 символов), а подсказка уже
  говорит о двух видах: «задание» и «ответ клиенту». В новой панели два поля, «Ответ клиенту» и «Задание боту»;
  консоль склеивает их в ту же заметку с подписями. Бот не меняется.

### Данные, которых сейчас нет, без правок бота

- «Новые» передачи: у бота нет отметки «просмотрено». Консоль хранит у себя, что пользователь уже видел.
- Расход в долларах у бота не считается. Обе стороны отдают токены по моделям, консоль считает деньги по одной таблице
  цен (из `leads/tanbala_leads/llm.py`). Расшифровка голосовых (OpenRouter) пишется только в журнал: показываем
  «не учтено».
- «Писали после письма» = первое сообщение клиента в чате с подтверждённой компанией позже первого настоящего письма.
  Сейчас настоящих отправок нет, а у импорта датой стоит день импорта: раздел будет почти пустым, с пометкой.
- Связь чат ↔ компания — только подтверждённая клиентом (`confirmed.id`). Кандидат показывается с пометкой
  «не подтверждено».

## 3. Вход и безопасность

- Пользователи в SQLite консоли, имя `[a-z0-9._-]{1,32}`, пароль от 9 до 256 символов (требование владельца; сверху
  пароль Caddy и ограничение попыток), хэш scrypt (`node:crypto`, без native-пакетов). Заводить, менять пароль и
  роль, отключать, закрывать сессии — только командой на сервере (`console-user.sh`, пароль без эха). В интерфейсе
  пользователи только для чтения.
- Роли проверяет сервер консоли на каждом маршруте, по умолчанию отказ; роль и «активен» читаются из базы на каждом
  запросе. Тест обходит все маршруты и падает, если у маршрута не объявлена роль.

| Действие | Владелец | Менеджер |
| --- | --- | --- |
| смотреть главную, чаты, клиентов, компании, письма, поиск, проверки из WhatsApp, уведомления, «кому писали» | да | да |
| ответ клиенту, «Вернуть боту», отметка «видел» | да | да |
| запуск поиска, одобрить, отклонить, изменить, тест письма, «Больше не писать», «Снять отметку WhatsApp», импорт | да | нет |
| «Система»: расход по дням, журнал действий, пользователи и сессии | да | нет |

- Сессия: cookie `__Host-tanbala_console` (HttpOnly, Secure, **SameSite=Strict**: страница — SPA, её запросы к `/api`
  идут с того же сайта, поэтому ссылка из WhatsApp всё равно открывается без нового входа; `index.html` и статика
  отдаются без сессии). В базе только SHA-256 от id. Живёт 30 дней, без активности 7 дней; фоновые опросы срок не
  продлевают (заголовок `X-Console-Poll`). Не больше 10 сессий на пользователя, вытесняются только свои. Новый id при
  входе. Экран «Сессии»: устройство, IP, последняя активность, «закрыть» и «выйти везде».
- GET ничего не меняет (тест). CSRF: только `application/json`, заголовок `X-CSRF-Token` и проверка Origin; у входа
  и выхода Origin обязателен. Тело: 64 КБ, импорт 1.5 МБ.
- Попытки входа: попытка засчитывается до расчёта хэша; 5 за 10 минут на IP и 10 за час на любое имя; одна проверка
  сразу на IP и на имя, всего 2 расчёта scrypt и очередь до 4, сверх — 429 без расчёта. Для несуществующего имени
  тот же расчёт хэша. `trustProxy` только 127.0.0.1, в Caddy `trusted_proxies` не включать.
- fail2ban: свой jail по журналу Caddy на `POST /api/login` 401/429. Консоль отвечает 401 **только** на неверный
  пароль. «Нет сессии» — 403; 401 и 403 от почты или бота консоль превращает в 502 `backend_auth`. Страница на 401
  и 403 останавливает опросы до действия человека, на сетевые сбои повторяет с растущей паузой.
- Посредник без общего прокси: каждый маршрут `/api` — свой обработчик с ролью; id только целые (zod); адрес к
  почте и боту собирается из шаблона; ответ проверяется схемой и отдаётся заново своим JSON. Заголовки, статус и
  `Content-Type` от почты и бота наружу не идут. Одинаковые одновременные запросы объединяются, кэш 1–2 с, не больше
  4 запросов сразу к каждому приложению, таймаут, предел ответа, списки id до 100.
- Заголовки: CSP `default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data:;
  font-src 'self'; manifest-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'; object-src
  'none'`, никогда `'unsafe-inline'`; Host только panel.tanbala.kz и локальный; nosniff, DENY, Referrer-Policy
  same-origin, Permissions-Policy, COOP и CORP same-origin, no-store для данных, HSTS.
- Чужой текст (сайты, 2ГИС, WhatsApp, модель) — только как текст: в React запрещены `dangerouslySetInnerHTML` и
  `innerHTML` (ESLint). Внешние ссылки только через одну функцию `safeExternalUrl` (http/https, без логина в
  адресе), `tel:` и `wa.me` собираются только из цифр, внутренние ссылки — из id.
- Журнал действий: вход, выход, неудачи (имя — только если такой пользователь есть), каждое действие (кто, что,
  над чем), без паролей, текстов и номеров; хранится 180 дней. В логах скрыты cookie, `X-CSRF-Token`, токены, строка
  запроса; из ошибок схем — только путь и код.
- Подтверждение листом снизу у всех опасных действий, с текстами старых панелей: запуск поиска (цена), ответ
  клиенту (бот в чате замолчит), одобрить, отклонить (письмо больше не появится), «Больше не писать» (не
  отменяется), «Снять отметку WhatsApp» (компания может попасть в рассылку), тест письма (уйдёт только на <адрес>,
  N из 30 за день), правка одобренного письма (одобрение снимется). Кнопка выключена, пока запрос идёт.
  Переключателя `TEST_MODE` в панели нет.
- Служба: свой пользователь `tanbala-console`, защита systemd как у почты, память до 300 МБ. В nftables правила
  консоли стоят до правила DNS: можно только 127.0.0.1:8000 и :3101, больше никуда; закрыты D-Bus и resolved.
- Пароль Caddy для panel — по строке на человека (`open-panels.sh panel add|remove <имя>`). Сотрудник ушёл:
  отключить пользователя консоли (закроет сессии) и удалить его строку Caddy.

## 5. Экраны

Сверху всегда полоса режима, собранная из состояния: бот (`TEST_MODE`: «отвечает только номерам из списка» /
рабочий режим / «бот недоступен» / «WhatsApp не подключён») и почта («тестовые письма только на <адрес>» или
«тестовая отправка выключена»), всегда с фразой «компаниям письма не отправляются».

Подробности, которые нельзя потерять (из проверки плана): сообщения после действий по коду исхода (у бота
`sent`, `duplicate`, `returned`, `returned_answering`, `already_bot` — «заметка не сохранена»; у почты тексты
старого интерфейса); понятные причины отказа; сводка для руководства (найдено, подходят, средняя оценка, одобрено;
компании из WhatsApp отдельно); бюджет почты — из её же расчёта (`spent_today_usd`), полоска с красным при
превышении, «N токенов без цены», расход всего и на компанию; страницы и общее число записей везде; фильтр писем по
запуску; порядок очереди писем как сейчас.

1. **Вход.** Имя, пароль.
2. **Главная «Требует внимания».** Новые передачи от бота (причина, уровень, когда, дошло ли уведомление — красным,
   если нет); горячие клиенты; ждут ответа (у менеджера: клиент написал после последнего ответа человека; у бота:
   клиент ждёт дольше 5 минут — сбой); писали в WhatsApp после письма; что идёт сейчас (поиск с этапом и полоской,
   проверки из WhatsApp, чаты простоя, подключён ли WhatsApp); расход API за сегодня и месяц (бот, почта, остаток
   дневного бюджета почты и вызовов бота); письма ждут проверки. Каждая строка ведёт в карточку.
3. **Чаты.** Список: имя, номер, кто ведёт, уровень, компания, последнее сообщение, «ждёт N мин». Фильтры: статус,
   уровень интереса, компания (подтверждена, кандидат, нет), поиск по имени и номеру.
4. **Клиент — единая карточка.** Переписка (голосовые помечены, бот, менеджер с телефона и из панели различаются
   цветом), снизу поле ответа (выключено с причиной, если WhatsApp не подключён или чат вне списка); рядом: статус
   и кто решил, выжимка о клиенте и почему такой уровень, заметка для бота, открытая передача и история передач,
   отклонённые черновики с замечаниями, последнее уведомление менеджеру. Компания двумя блоками: «что знает бот»
   (состояние определения, как найден кандидат, проверка новой компании, боли со слов клиента, название со слов
   клиента) и «данные почты» (2ГИС, оценка, боли с цитатами, письма ей; у кандидата заметная пометка «не
   подтверждено»). «Вернуть боту» с полями «Ответ клиенту» и «Задание боту», с прежним предупреждением (бот может
   пересказать заметку клиенту; без скидок, маржи и внутренних указаний; цифры бот назовёт только из заметки),
   счётчик по итоговой склейке до 1000 символов. После 502 при ответе: «Не отправлено, чат уже у менеджера, бот
   молчит» и кнопка «Вернуть боту».
5. **Компании.** Список с фильтрами и сортировкой; карточка: 2ГИС, оценка и причина, боли с цитатами, почты и
   проверки, письмо, история писем, тестовые отправки, текст сайта (свёрнут), отметка «писал в WhatsApp» и «Снять
   отметку», «Больше не писать», ссылка на чат WhatsApp, если он есть.
6. **Письма.** Очередь «ждут проверки / одобрены / отклонены / все», письмо: проверки, заметки для вас, правка,
   одобрить, отклонить, тест, скопировать; после действия — следующее письмо.
7. **Поиск.** Отрасли (подсказки), город, компаний на отрасль, цена до запуска, ход запуска по этапам вживую,
   прошлые запуски (можно открыть ход любого). Вкладка «Проверки из WhatsApp».
8. **Кому писали.** История писем, «не писать», два импорта (текст или файл .txt/.csv до 1 МБ).
9. **Уведомления менеджеру.** Все уведомления с именем клиента, фильтр по статусу (сбой, номер не задан).
10. **Система** (владелец). Состояние бота и почты, лимиты за сутки, расход по дням, журнал действий, пользователи.

Обновление само: главная раз в 15 с, открытый чат раз в 5 с, ход поиска раз в 2 с, только пока вкладка открыта.
Значки в меню: новые передачи, ждут ответа, письма на проверке.

## 6. Телефон (390 px)

## 7. Память (сервер 2 ГБ + swap 4 ГБ)

## 9. Риски

1. **Память** (раздел 7): поиск идёт через swap.
2. **Бот меняется**: на сервер пойдёт новый коммит, не 99e60a1. Защита: старые 4508 тестов без правок, новые тесты на
   эндпоинты и на одинаковость старых и новых кнопок, ревью.
3. **Уже сейчас**: интерфейс почты на 127.0.0.1:8000 принимает кнопки без проверки Origin, а бот по nftables может
   туда ходить. Взломанный бот мог бы нажать, например, платный поиск (в пределах $1 в день). Решение владельца:
   закрыть старый интерфейс почты для всех, кроме Caddy. Проверка Host или Origin этого не делает, поэтому
   интерфейс уходит на свой порт 8001 (раздел 2) уже на этапе 1; удаляется вместе со старыми панелями по «ок».
4. **Ответ из панели при упавшей связи WhatsApp**: сейчас чат уходит менеджеру, а отправка падает (502). Новая
   панель показывает состояние связи заранее и честно пишет «не отправлено». Логику бота не меняем.
5. **fail2ban** может забанить своего, если считать 401 на опросы: решено ответом 403 (раздел 3).
6. **Импорт писем без даты**: «писали после письма» пока почти пусто (раздел 2).
7. **Срок**: самый долгий этап — интерфейс; режу полировку, а не функции.
