### Неудобства сейчас (учесть в новой панели)

- Одобрение письма — одно нажатие без подтверждения, а на телефоне «Одобрить» и «Отклонить» стоят рядом в сетке 2×2 в липкой панели снизу: легко нажать не ту кнопку (отклонение спрашивает подтверждение, одобрение — нет).
- Подтверждения сделаны системным window.confirm: на телефоне это голое окно браузера без деталей письма/компании; без JS действия проходят без подтверждения.
- Живого обновления нет нигде, кроме страницы «Поиск»: значок «Письма», очередь и список компаний не обновляются сами; уйдя со страницы поиска, не узнать, что запуск закончился (нет уведомлений).
- CSRF-токен один на процесс и меняется при каждом перезапуске сервера: открытая на телефоне вкладка при нажатии получает 403 «Форма устарела…», введённый текст правки письма теряется (страница ошибки форму не возвращает).
- Страница ошибки ведёт только «На страницу поиска», без возврата к письму или компании, откуда пришёл владелец.
- Очередь писем показывает только первые 100 без пагинации; на телефоне список — отдельная прокручиваемая область 320 px над письмом (вложенная прокрутка), письмо ниже.
- В списке компаний нет выбора сортировки (только «новые сверху»): нельзя отсортировать по оценке, дате письма или качеству почты; нет фильтров «из WhatsApp», «писал в WhatsApp», «в списке не писать», «есть письмо».
- Текстовый поиск по компаниям требует кнопку «Показать», а выпадающие фильтры применяются сразу — поведение непоследовательное; на телефоне подписи фильтров скрыты.
- Адрес почты в списке компаний обрезается многоточием (white-space: nowrap) — на узком экране длинные адреса не видны целиком.
- Нет обратных действий: снять компанию/домен/адрес из «не писать» нельзя, удалить ошибочную строку импорта нельзя; отменить одобрение можно только через «Изменить» или «Отклонить».
- Обещание «Новый черновик напишет следующий запуск» (после отклонения) неверно: pipeline.UNFINISHED_SQL пропускает компании с любым черновиком, а дубли из 2ГИС не добавляются — письмо этой компании больше не появится.
- Если письмо компании из WhatsApp пытаются одобрить, триггер БД даёт CheckViolation, а интерфейс показывает 409 «У компании уже есть другое активное письмо.» — непонятная причина.
- Импорт «Уже писали» адреса, который есть в «не писать», засчитывается как «уже были» без объяснения (CheckViolation считается пропуском).
- Подсказка «Из CSV берётся первая колонка» неверна: берутся все куски с «@» или точкой из всех колонок; сайты из CSV в форме «Уже писали» попадают в «не распознано».
- Карточка компании на телефоне очень длинная: «Почему подходит» идёт первым, письмо вторым, текст сайта до 20 000 символов в одном блоке; действия по компании («Больше не писать») спрятаны в середине страницы в блоке «История писем».
- Владелец не видит дневные лимиты: тестовых отправок осталось из 30, проверок WhatsApp из RESEARCH_PER_DAY; о лимите узнаёт только по ошибке. Бюджет проверяется только при старте запуска, во время запуска расход может превысить лимит без предупреждения.
- Нет экрана проверок из WhatsApp (research_jobs): что бот проверял, что не нашлось в 2ГИС, что упало, сколько стоило.
- В шапке на телефоне сумма расхода показана без подписи (spend-label скрыт) — непонятное число; полоса тестового режима занимает место на каждой странице.
- Поиск только по свободному тексту отрасли, без выбора рубрики 2ГИС; лимиты 20 на отрасль и 60 за запуск видны только в подсказках и ошибках.
- «Скопировать» копирует и подпись, и заметки-строки внутри текста; кнопка вовсе не появляется без Clipboard API.
- Счётчик «Ждут проверки» и KPI не кликабельны в сторону конкретного запуска; ссылки «Проверить письма» и «Смотреть компании» появляются только после окончания запуска.
- Телефоны в карточке 2ГИС только tel:, нет быстрых ссылок WhatsApp или mailto для адресов (если владелец захочет связаться сам).
- Кто одобрил — всегда «владелец» (константа): при нескольких людях за паролем Caddy нельзя понять, кто нажал кнопку.
