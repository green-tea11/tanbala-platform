# Правила для Claude в D-Email+WhatsApp

Здесь сведены два проекта Tanbala и всё для общего сервера. Владельцу пиши по-русски, коротко и просто: логику
проекта он знает, детали кода нет.

## Папки

- `leads/` — проект B (B-web-email): поиск компаний, письма, внутренний API. Python, FastAPI, Postgres и Reacher
  в Docker, parser-2gis с Chrome, crawl4ai с Chromium. Свои правила: `leads/CLAUDE.md`, `leads/HANDOVER.md`.
- `whatsapp/` — проект C (C-WhatsApp): бот-консультант. Node 22, TypeScript, Baileys, SQLite, панель fastify.
  Свои правила: `whatsapp/CLAUDE.md`, `whatsapp/docs/DEPLOY.md`.
- `deploy/` — всё для сервера. `contract/INTERNAL_API.md` — контракт API между проектами. `handover/` — передача
  от агентов B и C, итог слияния в `handover/MERGE.md`.
- Оригиналы `..\B-web-email` и `..\C-WhatsApp` только читать, не менять: это резервная копия. Оригинал C после
  этапа 2 не запускать: его сессия WhatsApp переехала в `whatsapp/data`, две копии одной сессии ломают её.

Этот файл главнее вложенных `CLAUDE.md` в границах папок: их правила «не открывай соседние папки» и «в общей папке
только handover и contract» здесь не действуют. Остальные правила проектов (код, тесты, платный API, запреты)
действуют внутри своих папок.

## Правила владельца

- Секреты (`.env`, ключи, пароли, токены) не выводить в чат и не класть в git. `.env` на сервер переносит владелец,
  Claude даёт команду scp.
- Реальные вызовы Claude API, поиски в 2ГИС, отправка писем — только после «ок» владельца, с оценкой стоимости.
- `TEST_MODE` у бота остаётся `true`, пока владелец отдельно не скажет его выключить.
- WhatsApp: новый QR только на сервере, только по команде владельца, не больше двух попыток привязки в сутки.
  Перед этим бот на ПК остановлен.
- Один коммит на пункт. После каждого этапа отчёт и стоп до «ок». Помощники на Opus, полноценные ревью кода
  и безопасности.
- Docker на ПК: только контейнеры проекта compose `tanbala-leads` (том `tanbala-leads_pgdata`, имя задано
  в `leads/docker-compose.yml`). Второй Postgres и Reacher не поднимать, том не удалять и не пересоздавать.

## Сервер

- PS.KZ, Ubuntu 24.04, 91.201.215.210, вход `ssh ubuntu@91.201.215.210` по ключу, sudo без пароля.
- Уже есть: Asia/Almaty, автообновления безопасности, swap 4 ГБ, ufw (22, 80, 443), fail2ban. Память 4 ГБ, 2 vCPU,
  диск 40 ГБ.
- Docker обходит ufw: порты контейнеров публиковать только на `127.0.0.1`.
- `wa.tanbala.kz` — панель бота, `leads.tanbala.kz` — интерфейс почты. Обе за basic auth Caddy, у панели бота
  ещё свой пароль. Внутренний API только на `127.0.0.1`. Сам `tanbala.kz` не трогать: там будет сайт.

  дать владельцу готовый текст обращения в поддержку PS.KZ.
