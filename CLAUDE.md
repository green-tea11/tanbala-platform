# C-WhatsApp: WhatsApp-консультант Tanbala

Перед работой прочитай: `docs/PLAN.md` (план; для WhatsApp он главнее документа владельца), `knowledge/tanbala-agent.md`, `knowledge/whatsapp.md` и решения в `docs/adr/`.

## Правила владельца

- Владельцу пиши по-русски и коротко.
- Работай только в этой папке. Папки `A-site`, `B-web-email` и другие не открывай и не меняй. Если что-то оттуда нужно, спроси владельца.
- Реальные вызовы Anthropic API и OpenRouter только с разрешения владельца. Тесты только на моках.
- QR-код не запускай и к WhatsApp не подключайся, пока владелец не скажет. Поэтому без разрешения не запускай `npm run dev` и `npm start` и не меняй `WA_ENABLED=false`.
- Один коммит на пункт задания, формат `<type>: <описание>`.

## Технические правила (из плана)

- Ключ Claude только из `VENMART_ANTHROPIC_KEY`, передаётся в SDK явно. `ANTHROPIC_API_KEY` не использовать нигде.
- Модели в `config/models.json`: ответ и решение о передаче на Sonnet 5.5, проверка черновика и выжимка на Haiku 5.5 (решение владельца 26.10.2026). Каждый вызов API пишется в лог токенов: модель, входные и выходные токены.
- Папка сессии Baileys и `.env` не попадают в git и никуда не копируются.
- Бот пишет только в ответ на входящие и менеджеру на `MANAGER_WHATSAPP`.
- Панель на ПК слушает только `127.0.0.1`. С паролем `admin` на другом адресе панель не запускается. На VPS только HTTPS и пароль не короче 16 символов.
- Тексты для клиентов и файлы знаний пишутся без тире.

## Решения владельца (25.10.2026)

- Поводы передачи менеджеру: горячий клиент, нет ответа в знаниях, проверка не пройдена, жалоба, просьба о живом человеке. Технические поводы: ошибка API (`llm_error`) и превышен лимит.
- Голосовые расшифровываются с этапа 3 (перенесено с этапа 7 решением от 26.10.2026): OpenRouter, модель в `config/models.json`, расшифровка идёт как обычный текст клиента. Если расшифровка не удалась, бот отвечает ровно «Сейчас не могу прослушать голосовое, напишите, пожалуйста, текстом» и больше ничего.
- Номер менеджера пока не задан (26.10.2026): при пустом `MANAGER_WHATSAPP` уведомления пишутся в лог (без имён, номеров и текста клиента) и показываются в панели. Отправка на номер покрыта тестами на моках и заработает без правки кода, когда номер появится в `.env`.
- Бот работает только с сообщениями, пришедшими после привязки номера. Старые пропускает полностью: без ответа и без отметки.
- Простой бота: сообщениям не старше `BACKLOG_MAX_AGE_HOURS` (12 часов) бот отвечает как обычно, один ответ на чат. На более старые не отвечает и не отмечает их прочитанными, а шлёт менеджеру одно уведомление со списком таких чатов.
- Предохранитель: не больше `API_DAILY_LIMIT` вызовов API в сутки на весь бот и `API_DAILY_LIMIT_PER_CHAT` на один чат (500 и 100, в `.env`). При превышении бот замолкает в этом чате (без фразы клиенту) и уведомляет менеджера.
- Тестового номера нет: этап 2 идёт на рабочем номере в закрытом режиме. Пока `TEST_MODE=true`, бот обрабатывает только номера из `TEST_ALLOWLIST`, остальные чаты полностью игнорирует: не сохраняет переписку, не читает, не отмечает прочитанными, не отвечает, не уведомляет менеджера.
- Этап 8, выключение `TEST_MODE`: все чаты с перепиской до переключения получают статус «ведёт менеджер», бот берёт только чаты, которые впервые написали после переключения. Поэтому с момента привязки бот запоминает номера чатов с перепиской и время последней активности, без текста: список чатов из первой синхронизации WhatsApp и любые новые сообщения, в том числе в чатах вне `TEST_ALLOWLIST`.
- Привязка по QR: не больше 2 попыток за скользящие 24 часа, счётчик в базе. Третью попытку запрещает код (константа `PAIRING_MAX_ATTEMPTS_PER_DAY`, не настройка).
- Трансграничную передачу текстов клиентов в Anthropic владелец уточняет у юриста; работу это не останавливает.
- Проверки кодом перенесены из `docs/reference/` (образец из B-web-email, его прислал владелец). В саму B-web-email не заходить.

## Код

- Node.js 22, TypeScript strict, ESM: относительные импорты с расширением `.js`, файлы в kebab-case, без `export default` и без `enum`.
- Внешние библиотеки только в своих адаптерах: `baileys` в `src/whatsapp`, `@anthropic-ai/sdk` в `src/llm`, `better-sqlite3` в `src/db`, `fastify` в `src/panel`. Остальной код работает через интерфейсы `src/domain`. Это проверяет `tests/guards/architecture.test.ts`: конфиг ESLint защищён хуком ECC, правила архитектуры живут в тестах.
- Зависимости модуля передаются параметрами, без глобальных синглтонов. При импорте модуль ничего не запускает и никуда не подключается.
- Логи только через pino. Текст сообщений, номера клиентов и ключи в логи не пишутся.
- Зависимости: точные версии, install-скрипты отключены в `.npmrc`, новые версии не моложе 7 дней.
- Заготовок с `NotImplementedError` больше нет: к этапу 6 все функции реализованы, растяжка `tests/stubs/contract.test.ts` удалена. Новая функция сразу пишется с тестами (TDD).
