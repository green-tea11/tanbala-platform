## Как устроено

| Часть | Служба | Пользователь | Адрес внутри | Снаружи |
| --- | --- | --- | --- | --- |
| Единая панель (`console/`) | `tanbala-console` | `tanbala-console` | 127.0.0.1:3200 | https://panel.tanbala.kz (пароль Caddy + вход панели) |
| Почта (`leads/`): API | `tanbala-leads` | `tanbala-leads` | 127.0.0.1:8000, только `/internal/*` | нет |
| Почта: старый интерфейс | та же | та же | 127.0.0.1:8001 | https://leads.tanbala.kz (закрыт до пароля Caddy) |
| Бот (`whatsapp/`): старая панель | `tanbala-whatsapp` | `tanbala-wa` | 127.0.0.1:3100 | https://wa.tanbala.kz (закрыт до пароля Caddy) |
| Бот: API для панели | та же | та же | 127.0.0.1:3101 | нет |
| Postgres, Reacher | Docker | root | 127.0.0.1 | нет |
| Сайт | Caddy | caddy | `/srv/tanbala-site/current` | https://tanbala.kz |

- Панель — посредник: в браузер не уходят токены почты и бота, роли (владелец и менеджер) проверяет сервер
  панели. Действия идут в почту и бота теми же функциями, что кнопки старых панелей.
- Токены (сгенерированы на сервере 30.10.2026, в чат и git не попадали):
  - `INTERNAL_API_TOKEN` — бот ↔ почта;
  - `LEADS_CONSOLE_TOKEN` — панель ↔ почта (`.env` почты и панели);
  - `WA_CONSOLE_TOKEN` — панель ↔ бот (`.env` бота и панели).

  Все три разные; при совпадении службы не стартуют.
- Правила nftables:
  - панели можно только на 8000 и 3101;
  - Caddy — только на 3100, 3200 и 8001;
  - боту — только на 8000;
  - остальным пользователям, кроме root, на эти порты нельзя. Поэтому проверки на сервере делаются через `sudo`.
- Каждая служба может занять только свои порты (`SocketBind` в systemd). Бот с токеном панели выходит, если порт
  3101 занят.
- На сервере панель по `127.0.0.1` отвечает только на `/healthz`, всё остальное идёт через Caddy.
- Закрытый режим бота включён (`TEST_MODE=true`, в списке 1 номер). Тестовые письма уходят только на адрес
  владельца, компаниям письма не отправляются.

Подробно: `console/docs/PLAN.md` (план и решения), `contract/CONSOLE_API.md` (API между частями),
`console/docs/API.md` (API панели для браузера), `deploy/README.md` и `deploy/env.md` (сервер).

## Как обновлять

1. ПК (Git Bash, корень репозитория, всё закоммичено):
   ```
   bash deploy/scripts/build-release.sh
   ```
   Архив собирается из последнего коммита; панель и её интерфейс собираются на ПК.
2. Отправка (имя архива и команду скрипт печатает сам):
   ```
   scp release/tanbala-<sha>.tar.gz ubuntu@91.201.215.210:~/
   ```
   Сверить `sha256sum` с тем, что напечатал скрипт.
3. Сервер:
   ```
   tar -xzf ~/tanbala-<sha>.tar.gz -C ~ && sudo bash ~/tanbala-<sha>/deploy/scripts/install.sh <шаги>
   ```
   Шаги: `system configs leads whatsapp console` или `all`. Обновить только одну часть — её шаг: бот
   останавливается и запускается сам, сессия WhatsApp не трогается.
4. Проверка:
   ```
   sudo /opt/tanbala/deploy/scripts/health.sh
   ```
   Должно быть «OK» по всем строкам.
5. Сайт:
   ```
   bash deploy/scripts/site.sh
   ```
   Это с ПК, сборка из последнего коммита `../A-site`; откат — `site-install.sh --rollback`.

Привязка WhatsApp по QR — только `pair-whatsapp.sh` (`deploy/README.md`, «Этап 4»), не больше двух попыток в
сутки. Копии баз — каждую ночь в 03:30 (`/var/backups/tanbala`, 7 дней): Postgres, база бота и база панели.
