# Handover

Обновлено: 28.10.2026. Этап: внутренний API для WhatsApp-бота и отметка «клиент писал в WhatsApp» готовы, реальная проверка с замером памяти проведена; ждём «ок» владельца. Тестовое письмо не дошло до Gmail из-за PTR почтового сервера (см. ниже).

## Проект

Система поиска клиентов для Tanbala (RFID-направление ТОО «VenMart», Алматы). Каждый день: казахстанские компании из 2ГИС, проверенная почта, причина «почему им подходит» и черновик письма. Письмо уходит только после одобрения человеком.

Пайплайн и статусы компании: `new` (2ГИС) → `crawled` (сайт) → `qualified` / `rejected` (Claude) → `verified` (Reacher) → `drafted` (черновик) → `approved` (человек) → `sent` → `replied`.

Правила работы: [CLAUDE.md](CLAUDE.md). Установка и запуск: [docs/SETUP.md](docs/SETUP.md).

### Доработки для проекта C и VPS 4 ГБ (28.10.2026)

Задание владельца после отчёта: Host с портом, телефоны не в логе, пометки WhatsApp, кнопка снятия, общий лимит браузеров. Реальных вызовов API и поисков 2ГИС не было.

- **Host с портом.** Агент C писал, что `Host: 127.0.0.1:8000` получает 400. Сервер такие запросы уже принимал (Starlette сравнивает имя без порта; проверено curl на живом сервере: 200 / 401), агента сбила фраза контракта «Host должен быть 127.0.0.1 или localhost». Тесты закрепляют: `127.0.0.1:8000`, `localhost:8000`, без порта и в любом регистре доходят до проверки токена; `host.docker.internal:8000`, чужое имя, пустой или нечисловой порт — 400. В контракте уточнено. Если у C всё ещё 400, значит он шлёт другой Host (например, из Docker).
- **Номера клиентов не в логе.** uvicorn писал в access-лог путь со строкой запроса (`/internal/lookup?phone=…`). Теперь у путей `/internal/...` строка запроса отбрасывается целиком: телефон, почта (domain) и название (`HideInternalQuery` в `web/internal.py`, подключён через `log_config()` в `web/app.py`). Остальные пути пишутся как раньше. Тест поднимает настоящий uvicorn с настройками `serve()`; без фильтра он падает.
- **Пометка «запрошено из WhatsApp» только у компаний, которые research создал сам.** Так и было сделано (пометка ставится в той же вставке `collect.save_card`). Добавлены тесты на два пути к уже известной компании: найдена у нас по телефону; у нас под другим названием, но 2ГИС дал её же карточку. В обоих случаях пометки нет, отметки «писал в WhatsApp» тоже (её ставит только brief), а следующий поиск берёт компанию в работу как обычную.
- **Кнопка «Снять отметку WhatsApp»** в карточке компании (`POST /companies/{id}/whatsapp-clear`, CSRF и своё Origin, подтверждение `data-confirm`). Видна, если у компании есть хоть одна пометка; снимает обе сразу: отметку «писал в WhatsApp» и `requested_via`. После этого компания обычная: поиск может взять её в рассылку, новый brief снова поставит отметку. В карточке теперь видна и пометка `requested_via` («Компанию добавила проверка из WhatsApp. В рассылку она не попадает.»). Компанию 48 владелец снимет сам, Claude её не трогал.
- **Общий лимит браузеров (VPS 4 ГБ, на нём ещё WhatsApp-бот ≈ 0.3 ГБ).** `tanbala_leads/browsers.py`: на весь процесс `web` не больше `MAX_2GIS_BROWSERS` Chrome для 2ГИС и `MAX_SITE_BROWSERS` Chromium для сайтов (в `.env`, по умолчанию 1 и 1, допустимо от 1 до 4; плохое значение останавливает запуск до миграций с понятной ошибкой). Каждый вызов parser-2gis и каждый обход сайта в `pipeline.default_deps` сначала занимает место; `serve()` даёт поиску и очереди проверок один и тот же объект лимитов. Проверка из WhatsApp срочная: ждёт только текущий шаг поиска (одну выдачу 2ГИС или один сайт), а следующий шаг поиска ждёт её; параллельно с поиском может идти только браузер другого вида. Поиск из командной строки — отдельный процесс, лимит его не видит (на VPS искать только из интерфейса). По ревью Opus (код и безопасность): на Linux parser-2gis запускается в своей группе процессов и по таймауту убивается вместе с Chrome (раньше `os.kill` оставлял Chrome ≈ 1 ГБ жить, а место в лимите уже освобождалось); ждать место дольше предела нельзя (2ГИС 22 мин, сайт 5 мин), иначе шаг падает с `BrowserBusy`, а не висит до перезапуска; у проверки из WhatsApp parser-2gis ограничен 5 минутами (5 записей, обычно ≈ 15 с). Тесты на потоках: порядок «шаг поиска → проверка → следующий шаг», независимость видов, освобождение места при ошибке, разбор настроек, общие места у настоящих `default_deps`.
- **Расчётный пик с лимитом** (по замеру выше, рабочий набор): сервер ≈ 0.26 + Chrome 1.0 + Chromium 0.6 + драйвер 0.15 ≈ **2.0 ГБ** (было до 3.7 ГБ); с Postgres ≈ 0.22, Reacher и ботом ≈ 0.3 — **≈ 2.55 ГБ**, с системой и Docker ≈ **3.0 ГБ из 4 ГБ**. На VPS включить swap 1–2 ГБ и повторить замер на Linux.

## Открытые вопросы и известные ограничения

- **Reacher не ответил в запуске №3** (27.10.2026): 12 подходящих компаний остались без проверки почты (`ReacherUnavailable`). Причину не разбирали, владелец просил отложить. Гипотезы: таймауты SMTP-проверок с домашнего IP, контейнер перегружен очередью.

- Reacher с домашнего IP: SMTP-проверка даёт unknown (нет PTR и своего домена отправителя; tanbala.kz не существует в DNS, у venmart.kz SPF `-all`). Сейчас unknown считается годным, отсеиваем invalid. Полная проверка только на VPS со своим доменом.
- Тестовые письма не доходят до Gmail, пока у почтового сервера venmart.kz нет PTR (см. выше). То же ударит и по боевой отправке.
- Боевая отправка (когда появится) должна проверять `requested_via` в той же транзакции, что и отправку: триггер на `drafts.sent_at` сработает уже после SMTP.
- Поиск по названию в API сравнивает со всеми компаниями в Python: до тысяч компаний быстро, дальше `pg_trgm`.
- Файлы `pipeline.py` и `steps/collect.py` переведены с CRLF на LF (как остальные): в diff 0b286e5 они выглядят переписанными целиком, смотреть с `--ignore-cr-at-eol`.
- SSRF: остаётся теоретический DNS-rebinding (Python проверяет адрес, Chromium резолвит заново). Закрыть на VPS прокси или правилом брандмауэра для Chrome.
- Проверки кодом не ловят замаскированные ссылки (site[.]kz) и выдуманные факты: письмо всё равно читает человек.
- Сохраняются вопросы из прошлого этапа: подробное «ТЗ для Claude Code»; подтвердить документ о Tanbala; строгие правила базы; отдельный домен для рассылки.

## Решения и почему

| Решение | Почему |
| --- | --- |
| parser-2gis в отдельном окружении `.venv-2gis`, вызов как CLI | ему нужен pydantic<2, crawl4ai нужен pydantic>=2.10; в одном окружении не ставятся |
| Структура по 8 шагам пайплайна | раздела 5 подробного ТЗ нет, см. открытые вопросы |
| Список проверок писем в `checks.py` | раздела 3 ТЗ нет; взят из разделов 8, 11, 12 документа о Tanbala |
| Правила раздела 13 держит база | первое письмо на адрес и компании один раз (уникальные индексы в `contact_history`), триггер не даёт записать отправку адресу, домену с поддоменами или компании из `do_not_contact`, компанию с историей удалить нельзя |
| Порядок отправки (для `send.py`) | сначала строка в `contact_history`, потом SMTP, потом `drafts.sent_at`: сбой не даст повторного письма |
| Везде claude-haiku-5-5 | требование владельца; Sonnet только по его решению |
| `Anthropic(api_key=..., base_url=...)` явно | при явном ключе SDK 2.1 не ищет учётные данные в окружении; пустой ключ останавливает работу до создания клиента; base_url не даёт увести ключ через переменную окружения |
| В бесплатных тестах HTTP-запросы SDK заблокированы | защита бюджета; платные тесты только с `RUN_PAID=1` |
| Миграция 1 правилась до применения на сервере | база была пустой; дальше только новые миграции в конец `MIGRATIONS` |
| Сайт не открылся: работа продолжается по карточке 2ГИС | почта часто есть прямо в 2ГИС; иначе компания зависала бы на шаге «Сайты» |
| Незавершённые компании прошлых запусков дообрабатываются в пределах лимита запуска | ошибки API или Reacher временные; лимит запуска не растёт, а новые компании идут первыми |
| Компании без единой почты не уходят в Claude | писать некуда, вызов был бы потрачен зря |
| Суточный лимит `DAILY_API_BUDGET_USD` (по умолчанию $1, по времени Алматы) | бюджет владельца ограничен, кнопку можно нажать много раз |
| В письме допустим только наш номер WhatsApp | вредный текст на сайте мог бы подсунуть модели чужой номер |
| Ссылки `http://` из 2ГИС обходятся сначала по `https://` | переход http → https внутри браузера crawl4ai принимает за пустую страницу |
| Браузер crawl4ai в `.browsers`, всё остальное crawl4ai (global.yml, база, кэш) в `.crawl4ai` (пути задаёт `tanbala_leads/__init__.py`) | владелец требует держать всё в папке проекта: рядом агент сайта, файлы не должны смешиваться. Ставить и проверять только через `scripts/crawl4ai_tools.py` |
