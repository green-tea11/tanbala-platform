Перед работой прочитай: `docs/PLAN.md` (план; для WhatsApp он главнее документа владельца), `knowledge/tanbala-agent.md`, `knowledge/whatsapp.md`, `knowledge/consult.md` (как вести разговор, с 30.10.2026 главнее whatsapp.md в этом) и решения в `docs/adr/`.

## Правила владельца

- Владельцу пиши по-русски и коротко.
- Работай только в этой папке. Папки `A-site`, `B-web-email` и другие не открывай и не меняй. Если что-то оттуда нужно, спроси владельца.
- Исключение (27.10.2026): в общей папке `D-Email+WhatsApp` можно создавать и менять только `handover/C-WhatsApp.md` и читать `contract/INTERNAL_API.md`. Больше там ничего не трогать. С проектом B вживую ничего не связывать: только моки, слиянием займётся отдельный агент.
- Реальные вызовы Anthropic API и OpenRouter только с разрешения владельца. Тесты только на моках.
- QR-код не запускай и к WhatsApp не подключайся, пока владелец не скажет. Поэтому без разрешения не запускай `npm run dev` и `npm start` и не меняй `WA_ENABLED=false`.
- Один коммит на пункт задания, формат `<type>: <описание>`.

## Технические правила (из плана)

- Ключ Claude только из `VENMART_ANTHROPIC_KEY`, передаётся в SDK явно. `ANTHROPIC_API_KEY` не использовать нигде.
- Модели в `config/models.json`: ответ и решение о передаче, проверка черновика и выжимка на Sonnet 5.5, название с логотипа (`logo`) на Haiku 5.5 (решение владельца 29.10.2026, вместо Haiku для проверки и выжимки от 26.10.2026). Схема структурированного ответа каждого вызова не больше 16 полей с union-типами (nullable): иначе API отклоняет вызов (`tests/guards/llm-schemas.test.ts`). Каждый вызов API пишется в лог токенов: модель, входные и выходные токены.
- Папка сессии Baileys и `.env` не попадают в git и никуда не копируются.
- Бот пишет только в ответ на входящие и менеджеру на `MANAGER_WHATSAPP`.
- Внутренний API почтового проекта (контракт `D-Email+WhatsApp/contract/INTERNAL_API.md`): адрес `EMAIL_API_URL` (только 127.0.0.1), токен `INTERNAL_API_TOKEN` (секрет, как ключи), ссылка на карточку для менеджера `EMAIL_UI_URL`. Пустой токен: функция выключена, бот работает как раньше.
- Панель на ПК слушает только `127.0.0.1`. С паролем `admin` на другом адресе панель не запускается. На VPS только HTTPS и пароль не короче 16 символов.
- Тексты для клиентов и файлы знаний пишутся без тире.

## Решения владельца (25.10.2026)

- Поводы передачи менеджеру: горячий клиент, нет ответа в знаниях, проверка не пройдена (с 29.10.2026 только если не осталось безопасного вопроса, см. ниже), жалоба, просьба о живом человеке. Технические поводы: ошибка API (`llm_error`) и превышен лимит.
- Голосовые расшифровываются с этапа 3 (перенесено с этапа 7 решением от 26.10.2026): OpenRouter, модель в `config/models.json`, расшифровка идёт как обычный текст клиента. Если расшифровка не удалась, бот отвечает ровно «Сейчас не могу прослушать голосовое, напишите, пожалуйста, текстом» и больше ничего.
- Номер менеджера пока не задан (26.10.2026): при пустом `MANAGER_WHATSAPP` уведомления пишутся в лог (без имён, номеров и текста клиента) и показываются в панели. Отправка на номер покрыта тестами на моках и заработает без правки кода, когда номер появится в `.env`.
- Бот работает только с сообщениями, пришедшими после привязки номера. Старые пропускает полностью: без ответа и без отметки.
- Простой бота: сообщениям не старше `BACKLOG_MAX_AGE_HOURS` (12 часов) бот отвечает как обычно, один ответ на чат. На более старые не отвечает и не отмечает их прочитанными, а шлёт менеджеру одно уведомление со списком таких чатов.
- Предохранитель: не больше `API_DAILY_LIMIT` вызовов API в сутки на весь бот и `API_DAILY_LIMIT_PER_CHAT` на один чат (500 и 100, в `.env`). При превышении бот замолкает в этом чате (без фразы клиенту) и уведомляет менеджера.
- Тестового номера нет: этап 2 идёт на рабочем номере в закрытом режиме. Пока `TEST_MODE=true`, бот обрабатывает только номера из `TEST_ALLOWLIST`, остальные чаты полностью игнорирует: не сохраняет переписку, не читает, не отмечает прочитанными, не отвечает, не уведомляет менеджера.
- Этап 8, выключение `TEST_MODE`: все чаты с перепиской до переключения получают статус «ведёт менеджер», бот берёт только чаты, которые впервые написали после переключения. Поэтому с момента привязки бот запоминает номера чатов с перепиской и время последней активности, без текста: список чатов из первой синхронизации WhatsApp и любые новые сообщения, в том числе в чатах вне `TEST_ALLOWLIST`.
- Привязка по QR: не больше 2 попыток за скользящие 24 часа, счётчик в базе. Третью попытку запрещает код (константа `PAIRING_MAX_ATTEMPTS_PER_DAY`, не настройка).
- Трансграничную передачу текстов клиентов в Anthropic владелец уточняет у юриста; работу это не останавливает.
- Проверки кодом перенесены из `docs/reference/` (образец из B-web-email, его прислал владелец). В саму B-web-email не заходить.

## Решения владельца (27.10.2026): компания клиента

- Компанию ищем по очереди, сначала бесплатно: домен из бизнес-профиля WhatsApp (соцсети и общие почты не в счёт), номер, имя профиля (у обычного аккаунта только с признаком компании), название из слов клиента (в оценке интереса); логотип на фото профиля только у бизнес-аккаунта, один раз на чат. Ничего не нашли: бот один раз спрашивает, из какой компании клиент.
- Найденную компанию бот один раз уточняет («Вы из компании X, правильно?», с городом, если клиент назвал её сам). Справка идёт в промпт только после «да». «Нет»: компанию больше не предлагать. Неизвестную компанию проверяет проект B (research, один раз на чат).
- В промпт из справки только боли и рубрика, без evidence, source и цифр о клиенте. «Мы писали вам на почту» только при emailed true.
- Продажа: боли подаются как то, что бывает у похожих компаний, с вопросом. Принцип работы (подтверждён владельцем) объяснять любому клиенту: метку клеят на вещь, ридеры с антеннами на входах и выходах, а не на каждой полке, система сама отмечает приход и уход. Сколько ридеров и где ставить, бот не говорит.
- Цена: первый вопрос без рассказа о задаче не передаёт чат; после согласия с болью или рассказа о задаче, а также при втором вопросе цены передача hot с фразой «Цена сильно зависит от объёма. Передал ваш вопрос специалисту, он вам напишет.» (Заменено решением 29.10.2026: минимум, третий вопрос и новая фраза.)
- В уведомлении менеджеру: компания (или «не определена»), ссылка на карточку, подтверждённые боли.

## Решения владельца (29.10.2026): передача менеджеру

- Квалификация (уточнено владельцем 29.10.2026 вечером, второй раз): вопросы группами, в сообщении один блок из 2–3 коротких связанных вопросов (по возможности одним предложением) и не больше одной полезной фразы, которая не повторяет уже сказанное в чате. Группы по порядку, известное пропускается: компания и чем занимается; что учитывать (вещи, упаковка, материал: металл и жидкости важны для меток); где и сколько (город, тип помещения, число вещей); 1С и конфигурация. Площадь, движение, нынешний учёт и боли только в довесок к группе. Тон толкового менеджера: без «Понятно», «Хорошо» и пересказа слов клиента (ответ с «Понятно» в начале отклоняет код).
- Минимум перед передачей по цене: компания, что учитывать (тип и материал), количество, город и тип помещения, 1С (есть или нет). Остальное по возможности. Клиент спросил цену, а минимума нет: бот отвечает из знаний, «Ориентир коллега назовёт, когда поймём ваш объект» и вопросы следующей группы. Правило держит код: ранний hot по цене не передаёт чат. Фраза об ориентире только на ходу с вопросом цены (проверка кодом). (Минимум заменён готовностью к расчёту решением владельца 30.10.2026, см. ниже.)
- Пока чат ни разу не передавался (любая причина): собранный минимум сразу передаёт чат (hot), даже без вопроса цены, фраза «Спасибо, этого хватит, чтобы коллега назвал ориентир. Уточню у коллеги и вернусь к вам.»; пятое сообщение клиента без минимума тоже передаёт, фраза «Спасибо! Уточню у коллеги и вернусь к вам.» (при вопросе цены фраза о цене, ответ из знаний перед фразой, если клиент что-то спросил). После возврата боту эти правила не действуют. (Отменено решением владельца 30.10.2026: передачи по собранному минимуму и по пятому сообщению нет, бот ведёт разговор до финала.)
- «Вы нам писали на почту»: бот здоровается, обещает найти письмо и спрашивает компанию, без рассказа, как и кому мы пишем.
- Выжимка делает выводы из слов клиента с пометкой «вероятно»: «С 1С интегрируется?» значит «1С: вероятно есть, конфигурация не выяснена», а не «не выяснено». Вывод считается собранным для минимума.
- Без минимума чат передаётся сразу, только если клиент просит живого человека, отказывается отвечать, спрашивает цену четвёртый раз (29.10.2026 вечером, было третий) или жалуется. Сейчас счётчик вопросов цены обнуляется при возврате чата боту: это выбор реализации, владелец его ещё не подтвердил. (Заменено решением владельца 30.10.2026, см. ниже.)
- Черновик дважды не прошёл проверку (кодом или проверкой): чат не передаётся, бот отправляет безопасный вопрос из готового списка (один вопрос о следующей группе с недостающим, без фактов о нас). Передача `check_failed` только если такого вопроса не осталось.
- Отклонённые черновики и замечания проверки (оба круга) видны в карточке чата в панели, с датой, 30 дней. В общий журнал их тексты не пишутся.
- В уведомлении менеджеру: всё собранное по пунктам квалификации (выводы с пометкой «вероятно»), что из минимума собрано и что выяснить не удалось.
- Один голос: фраза передачи «Уточню у коллеги и вернусь к вам» без сроков, при цене «Цена сильно зависит от объёма. Уточню у коллеги и вернусь к вам.». Клиенту «коллега», а не «специалист»; обещать за другого человека («он вам напишет») нельзя: это проверяет код (`voice`) и проверка черновика.
- Возврат боту: бот отвечает на сообщения клиента, пришедшие после последнего исходящего (бота или менеджера) и не старше `BACKLOG_MAX_AGE_HOURS` (12 часов), одним ответом. Если после них менеджер уже ответил, бот молчит. Бот по-прежнему не пишет первым.
- Заметка для бота при «Вернуть боту»: необязательная, до 1000 символов, клиент её не видит, хранится в чате до следующей передачи и идёт в промпт ответа и проверки отдельным доверенным блоком «Указание коллеги». Задание бот выясняет группами вопросов, ответ клиенту передаёт своими словами как ответ коллеги. Цифры и обещания только из заметки: цена в ответе с теми же числами и валютой, что в заметке (проверка кодом), без заметки бот цену не называет.

## Решения владельца (30.10.2026): передача менеджеру

- Бот консультант ведёт разговор до финала. Передачи по собранному минимуму и по пятому сообщению клиента нет.
- Код передаёт чат (исход hot, `pipeline/handoff-gate.ts`, по выжимке после оценки этого хода): финал (модель вернула hot, для расчёта известно всё); клиент спрашивает цену, сроки или договор, а задача понятна (клиент согласился с трудностью или рассказал о задаче, известно, что на хранении и сколько); цену спросили третий раз; клиент два хода подряд уходит от вопросов (счётчик `chats.refused_streak`, возврат боту обнуляет). Просьба о человеке, жалоба и «нет ответа» как раньше. Hot модели без такой причины ранний: один повтор с замечанием, второй провал даёт безопасный вопрос; модель ответила answer, а причина есть (кроме финала), чат передаёт код.
- Фраза при передаче по цене и в финале «Я уточню у коллеги решение и ориентир под вашу задачу.», при уходах от вопросов «Уточню у коллеги и вернусь к вам.».

## Код

- Node.js 22, TypeScript strict, ESM: относительные импорты с расширением `.js`, файлы в kebab-case, без `export default` и без `enum`.
- Внешние библиотеки только в своих адаптерах: `baileys` в `src/whatsapp`, `@anthropic-ai/sdk` в `src/llm`, `better-sqlite3` в `src/db`, `fastify` в `src/panel`. Остальной код работает через интерфейсы `src/domain`. Это проверяет `tests/guards/architecture.test.ts`: конфиг ESLint защищён хуком ECC, правила архитектуры живут в тестах.
- Зависимости модуля передаются параметрами, без глобальных синглтонов. При импорте модуль ничего не запускает и никуда не подключается.
- Логи только через pino. Текст сообщений, номера клиентов и ключи в логи не пишутся.
- Зависимости: точные версии, install-скрипты отключены в `.npmrc`, новые версии не моложе 7 дней.
- Заготовок с `NotImplementedError` больше нет: к этапу 6 все функции реализованы, растяжка `tests/stubs/contract.test.ts` удалена. Новая функция сразу пишется с тестами (TDD).
